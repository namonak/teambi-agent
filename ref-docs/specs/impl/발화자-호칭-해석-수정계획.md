# 장부장 1인칭 오기입·직책 호칭 미해석 — 원인 및 수정 계획

**대상 저장소:** `teambi-agent` (`/Users/jchoi/study/teambi-agent`)
**teamMoneyManager 변경:** 없음
**작성일:** 2026-09-07

---

## 1. Context

두 가지 오해석이 함께 보고됐다. 이름은 이 문서에서 모두 가명(홍길동·김철수)으로 적는다.

### 1.1 1인칭("제가")을 엉뚱한 팀원으로 기입

발화자 A가 "장부장 김철수님과 제가 6,500원씩 사용했어요"라고 보냈는데, 봇이 "제가"를
**전혀 다른 팀원 B**로 기입했다.

원인(확정):

- `src/webhook.js:192`는 `activity.from?.name`을 `processNlAsync(text, requester)`에 넘기지만,
  그 값은 사후 게시 머리말(`:137`)에만 쓰이고 `runNlAgent`로는 전달되지 않았다.
- 동기 경로 `:195`의 `runNlAgent(text, deadline)`은 `from`을 읽지도 않았다.
- `buildSystem`(`src/nl-agent.js:16-49`)에는 **발화자 줄도 1인칭 규칙도 없었다.**

즉 모델은 "제가"가 누구인지 알 근거가 전혀 없는 상태에서 팀원 목록 중 하나를 골랐다.
정보 부족이지 모델 품질 문제가 아니다.

### 1.2 직책·호칭("실장님", "박실장")을 해석하지 못함

teamMoneyManager 회원 스키마는 `{id, name, birthday, active}`뿐이라 **직책·별칭 데이터가
서버에 존재하지 않는다.** 장부장 쪽 유일한 해석기 `resolveByName`(`src/tools.js:80-86`)은
정확 일치 → 양방향 substring뿐이라 `님`·직책을 벗기지 못했다.

| 입력 | 기존 동작 |
|---|---|
| `홍길동 실장님` | 역방향 `includes`로 우연히 통과 |
| `홍 실장님` / `홍실장` | 실패(0건) |
| `실장님` | 실패(0건) |
| `홍`(성만) | 동성 팀원이 둘이면 모호 |

teamMoneyManager 수정은 프로젝트 규칙상 금지 → **장부장에서 정규화 + `.env` 별칭 맵으로
흡수**한다(사용자 결정).

### 1.3 Teams `from.name`의 실제 형식은 미확인

테넌트 설정에 따라 `홍길동`, `홍길동 (Gildong Hong)`, `홍길동/부서` 등이 올 수 있다.
정규화로 여러 형식을 흡수하고, 수신 시 로그를 남겨 실서버에서 형식을 확정한다.

### 1.4 제약

- **5초 예산** — LLM 라운드·네트워크 호출을 하나도 늘리지 않는다(프롬프트 선주입만).
- **public repo** — 팀원 명단·직책을 코드·문서·테스트에 하드코딩하지 않는다. `.env`로만 받는다.
- 회신은 한국어, 원시 에러 노출 금지.

## 2. 설계 방침

- **발화자는 데이터로 준다.** 모델에게 추론시키지 않고 `from.name`을 팀원 목록과 대조해
  `발화자(이 메시지를 보낸 사람): 홍길동(id 11)` 한 줄로 프롬프트에 싣는다.
- **모르면 되묻는다.** 발화자가 목록에 없으면 `(팀원 목록에 없음)`으로 명시하고, 규칙으로
  "추측 기입 금지, 되묻기"를 지시한다. 잘못된 기입은 사용자가 알아채기 어려워 침묵보다 나쁘다.
- **이름 해석은 순수 함수로 분리**(`src/names.js`)해 단위 테스트로 경계를 못 박는다.
- **별칭은 `.env`로만.** 서버에 없는 정보(직책)를 서버에 만들지 않고 배포 설정으로 흡수한다.
- **네트워크·라운드 추가 0.** 별칭 파싱은 문자열 처리이고 발화자 해석은 이미 로드한
  `toolkit.members` 배열 조회다.

## 3. 변경 사항

### 3.1 `src/names.js` (신규, 순수 함수)

- `normalizeMemberRef(s)`: 괄호 부가정보 제거 → `/`·`|` 이후 제거 → 공백 제거 →
  끝 `님` 제거 → 끝 직책(`본부장|실장|팀장|부장|차장|과장|대리|사원|주임|이사|상무|전무|대표|매니저|PM|PL|프로|선임|책임|수석`)
  제거 → 다시 `님` 제거.
  - `'홍길동 실장님'→'홍길동'`, `'홍길동 (Gildong Hong)'→'홍길동'`, `'홍길동/BI팀'→'홍길동'`, `'실장님'→''`
- `matchMembers(members, ref, byKey)` → 0·1·n건 배열(throw 없음).
  순서: 원문 정확 → 정규화 정확 → 별칭 키 → 정규화 양방향 substring.
  정규화 결과가 빈 문자열이면 substring 단계를 건너뛴다(빈 문자열은 전원과 매칭되므로).
- `aliasKey(s)`: 공백 제거 + 끝 `님` 제거. 직책 자체가 별칭일 수 있어 직책은 벗기지 않는다.

### 3.2 `src/util.js` — `parseMemberAliases(str)`

`parseCardMap` 옆에 둔다. `"홍길동=홍실장,실장님;김철수=김팀장"` →

```js
{ byKey: Map{'홍실장'→'홍길동', '실장'→'홍길동', '김팀장'→'김철수'},
  labelsOf: Map{'홍길동'→['홍실장','실장님'], '김철수'→['김팀장']} }
```

- `byKey`는 해석용 키(공백 제거 + 끝 `님` 제거), `labelsOf`는 프롬프트 표시용이라
  사용자가 적은 원문·순서를 그대로 보존한다.
- 형식이 어긋난 항목은 조용히 건너뛴다. 같은 별칭이 겹치면 먼저 적은 쪽이 이긴다.

### 3.3 `src/tools.js`

- `resolveByName(list, name, label, matches = substringMatch)` — 매처 주입. 카테고리는 기존 동작 유지.
- `createToolkit()`에서 `parseMemberAliases(process.env.TEAMS_MEMBER_ALIASES)`를 읽어
  `resolveMember`(matchMembers 사용)를 만들고 `buildBody`의 `member_name` 해석에 쓴다.
  반환값에 `aliases`(byKey)·`aliasesOf(name)` 추가.
- `create_transaction`/`update_transaction`의 `member_name` 설명에
  "직책·호칭(실장님, 팀장님, 님)은 빼고 팀원 목록의 이름 그대로"를 명시.

### 3.4 `src/nl-agent.js`

- `speakerLineFor(toolkit, speaker)` export — 없음 → `(알 수 없음)`, 1건 → `홍길동(id 11)`,
  그 외 → `홍길동 (팀원 목록에 없음)`.
- `buildSystem(toolkit, opts)` — 팀원 블록 뒤에 `발화자(이 메시지를 보낸 사람): …` 한 줄 추가.
  별칭이 있는 팀원 줄에는 `[호칭: 실장님, 홍실장]`을 덧붙인다(없으면 기존 줄 그대로).
- 규칙 4줄 추가(출력 형식 규칙 앞):
  1인칭=발화자 / 발화자 미상이면 되묻기 / `member_name`은 호칭 제거 / `[호칭]`은 동일인.
- `runNlAgent(text, deadline, opts)`에 `opts.speaker` 추가 → `buildSystem`에 전달.

### 3.5 `src/webhook.js`

- `speakerFromActivity(activity)` export — `from.name`이 비지 않은 문자열이면 trim, 아니면 `null`.
- 핸들러에서 한 번 계산해 동기(`runNlAgent(text, deadline, { speaker })`)·비동기
  (`processNlAsync(text, speaker)` → `runNlAgent(..., { maxRounds, speaker })`) 양쪽에 전달.
- 자연어 경로에서 형식 확인용 로그 1줄: `[webhook] 발화자 from.name=%j` (본문·금액 미포함).
  `runNlAgent`도 해석 결과를 1줄 남긴다: `[nl-agent] 발화자 해석: 홍길동(id 11)`.

### 3.6 문서

- `.env.example`: `TEAMS_MEMBER_ALIASES` + 형식·예시(가명) 주석.
- `README.md`: 사용 예시("제가 커피 4,500원", "실장님 점심 12,000원"), 동작 설명,
  환경변수 목록, 로그 표, `src/` 트리에 `names.js`.

## 6. 범위 밖

- **`from.id`(AAD 오브젝트 id) 기반 매핑** — 표시명 변경에 견디는 정확한 방법이지만
  teamMoneyManager 회원 레코드에 저장할 곳이 없고 서버 수정은 금지다. 표시명이 자주 바뀌는
  문제가 실제로 생기면 `.env` 별칭으로 먼저 흡수한다.
- **서버 스키마에 직책 필드 추가** — teamMoneyManager 변경 금지 규칙에 걸린다.
- **직책으로 끝나는 실명 처리**(예: 이름 자체가 `…사원`으로 끝나는 경우) — 원문 정확
  일치가 정규화보다 먼저라 현재 구현으로 안전하지만, 그 이름을 호칭과 섞어 부르는 경우
  (`'○사원 대리님'`)까지는 다루지 않는다.
- **발화자 기반 권한 제어**(누가 누구 지출을 기입할 수 있는지) — 별도 과제.
