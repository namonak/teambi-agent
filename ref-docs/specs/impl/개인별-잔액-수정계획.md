# 장부장 개인별 잔액 답변 불가 — 원인 및 수정 계획

**대상 저장소:** `teambi-agent` (`/Users/jchoi/study/teambi-agent`)
**teamMoneyManager 변경:** 없음
**작성일:** 2026-08-18

---

## 1. Context

Teams 봇 "장부장"에게 팀원 **개인별 잔액**을 물으면 "확인할 수 없다"고 답한다.
공용 카테고리 잔액은 정상적으로 답한다.

원인을 추적한 결과 **teamMoneyManager 서버 결함이 아니다.** 서버는 개인별 잔액을 이미
정확히 내려주고 있고, 장부장이 그 데이터를 받아놓고 버리고 있다.

### 1.1 서버는 이미 주고 있다

`teammoneymanager/src/server.js:1340-1351` — `GET /api/dashboard`의 응답:

```json
{
  "categories": [ { "id": 1, "name": "커피", "allocated": 200000, "used": 72000, "remaining": 128000 } ],
  "members": [
    { "member_id": 11, "name": "홍길동",
      "allocation": 180000, "used": 52000, "remaining": 128000, "ratio": 0.288 }
  ]
}
```

`members[].remaining`이 곧 개인별 잔액이다. 계산은 서버의 `computeAllocation` 단일 소스를
거치므로 자투리(surplus)·조정(adjustment)까지 반영된 값이다.

### 1.2 장부장이 버린다

`teambi-agent/src/tools.js:91-94`:

```js
const [dashboard, membersRes] = await Promise.all([tmm.getDashboard(period), tmm.getMembers()]);
const categories = dashboard.categories ?? [];        // ← dashboard.members 를 읽지 않는다
const allMembers = membersRes.members ?? membersRes ?? [];
const members = allMembers.filter((m) => m.active !== 0);   // ← {id, name, active} 뿐. 금액 없음
```

`dashboard`를 손에 쥐고도 `categories`만 꺼낸다. 팀원 목록은 별도로 `/api/members`에서
가져오는데 이쪽 스키마에는 금액이 아예 없다.

### 1.3 그 결과 — 모델은 데이터도 도구도 없다

`teambi-agent/src/nl-agent.js:16-27`이 만드는 시스템 프롬프트:

```
당월 공용 카테고리(잔액):
- 커피(id 1): 잔액 128,000원 / 200,000원      ← 잔액 있음

활성 팀원: 홍길동(id 11), 김철수(id 12)        ← 이름과 id 뿐
```

여기에 더해 규칙(`nl-agent.js:30-31`)이 우회로까지 막는다:

```
- 위에 적은 카테고리 잔액과 팀원 목록은 이번 요청 시점의 최신 값이다. 잔액·팀원 질문은 도구 없이 이 값으로 바로 답한다.
- list_categories는 기입/수정/삭제를 실행한 직후 갱신된 잔액을 확인할 때만 호출한다. 그 외에는 절대 부르지 마라.
```

Gemini는 개인 잔액을 **컨텍스트에 가진 적이 없고**, 조회할 도구도 없으며, 도구 호출도
금지돼 있다. "확인할 수 없다"는 모델의 정직한 답변이다.

### 1.4 배제된 가설

| 가설 | 배제 근거 |
|---|---|
| 인증 실패(401) | 공용 카테고리 잔액은 정상 응답. 같은 쿠키를 쓰므로 인증은 살아 있다 |
| 과거 월 조회 (`members: []`) | `createToolkit`이 `currentPeriod()`만 사용 (`tools.js:89`) |
| 이름 → id 매핑 실패 | `resolveByName`(`tools.js:80-86`)은 정상 동작. 개인 지출 기입은 잘 된다 |

## 2. 설계 방침

- **teamMoneyManager는 건드리지 않는다.** 서버에 부족한 것이 없고, 장부장 CLAUDE.md의
  핵심 규칙("teamMoneyManager 수정 금지 — 모든 데이터 조작은 REST API 경유")에도 부합한다.
- **새 LLM 도구를 만들지 않는다.** 도구가 하나 늘면 LLM 라운드가 한 번(~1,150ms) 더 돌아
  Teams 4.2초 예산을 위협한다. `list_members`를 바로 그 이유로 이미 제거한 전례가 있다
  (`tools.js:14-17`). 카테고리 잔액과 똑같이 **시스템 프롬프트 선주입** 방식을 쓴다.
- **네트워크 호출을 늘리지 않는다.** 필요한 응답은 이미 `Promise.all`로 받고 있다.
  추가 지연 0ms.

## 3. 변경 사항

### 3.1 `src/tools.js` — `createToolkit`에서 잔액 병합

`:88-94`를 아래로 교체한다.

```js
export async function createToolkit() {
  const period = currentPeriod();
  // 시스템 프롬프트 선주입용 + 이름 해석용으로 미리 로드
  const [dashboard, membersRes] = await Promise.all([tmm.getDashboard(period), tmm.getMembers()]);
  const categories = dashboard.categories ?? [];
  const allMembers = membersRes.members ?? membersRes ?? [];

  // 개인 잔액은 dashboard.members에만 있다. 키가 member_id로, /api/members의 id와 다름에 주의.
  // resolveByName·summarize가 .id에 의존하므로 기존 배열 형태는 그대로 두고 금액만 얹는다.
  const balanceById = new Map((dashboard.members ?? []).map((m) => [m.member_id, m]));
  const members = allMembers
    .filter((m) => m.active !== 0)
    .map((m) => {
      const b = balanceById.get(m.id);
      return b ? { ...m, allocation: b.allocation, used: b.used, remaining: b.remaining } : m;
    });
```

**불변 조건**
- `members[].id` / `.name` / active 필터는 그대로 — `resolveByName`(`:121`)과
  `summarize`(`:149`, `:157`)가 여기 의존한다.
- `dashboard.members`가 `[]`여도(과거 월·서버 구버전) 병합이 no-op이 되어 기존 동작 유지.
- `:180`의 `return { ..., members, ... }`는 수정 불필요 — 같은 변수를 그대로 내보낸다.

### 3.2 `src/nl-agent.js` — 프롬프트에 개인 잔액 노출

`:19`의 `memberLine`을 카테고리(`:16-17`)와 같은 여러 줄 형식으로 바꾼다.

```js
  const memberLines = toolkit.members
    .map((m) =>
      m.remaining == null
        ? `- ${m.name}(id ${m.id})`
        : `- ${m.name}(id ${m.id}): 잔액 ${fmtWon(m.remaining)} / ${fmtWon(m.allocation)}`,
    )
    .join('\n');
```

`:27`의 템플릿 리터럴 한 줄을 교체:

```diff
-활성 팀원: ${memberLine || '(없음)'}
+활성 팀원(개인 잔액):
+${memberLines || '- (없음)'}
```

`fmtWon`은 `:9`에서 이미 import돼 있다.

### 3.3 `src/nl-agent.js:30` — 규칙 문구 보정

모델이 개인 잔액 질문에도 도구 없이 즉답하도록 명시한다.

```diff
-- 위에 적은 카테고리 잔액과 팀원 목록은 이번 요청 시점의 최신 값이다. 잔액·팀원 질문은 도구 없이 이 값으로 바로 답한다.
+- 위에 적은 공용 카테고리 잔액과 팀원별 개인 잔액은 이번 요청 시점의 최신 값이다. 잔액·팀원 질문은 공용·개인 모두 도구 없이 이 값으로 바로 답한다.
```

### 3.4 (선택) `src/tmm-client.js:60` 주석 갱신

현재 주석이 `{categories:[...]}`만 적어 `members[]`의 존재를 가린다. 이번 버그의
간접적 원인이므로 같이 고쳐 둔다.

```diff
-export const getDashboard = (period) => api('GET', `/api/dashboard?period=${encodeURIComponent(period)}`); // {categories:[{id,name,allocated,used,remaining}],...}
+export const getDashboard = (period) => api('GET', `/api/dashboard?period=${encodeURIComponent(period)}`); // {categories:[{id,name,allocated,used,remaining}], members:[{member_id,name,allocation,used,remaining}],...}
```

## 4. 테스트

### 4.1 기존 픽스처 수정 — `test/tools-personal.test.js`

현재 페이크 서버(`:29-38`)가 **모든 경로에 같은 body**를 돌려주고, 그 `members`는
`{id, name, active}` 형태다. 실제 `/api/dashboard`의 `members`(`member_id` + 금액)와
모양이 달라 병합 로직을 검증할 수 없다. 라우트별로 분기시킨다.

`:29-38`의 catch-all 직전에 dashboard 분기를 추가:

```js
    if (req.url.startsWith('/api/dashboard')) {
      // 실제 서버와 동일하게 members는 member_id 키 + 금액 필드를 갖는다.
      res.writeHead(200, { 'Content-Type': 'application/json' });
      return res.end(
        JSON.stringify({
          categories: [{ id: 1, name: '커피', allocated: 10000, used: 0, remaining: 10000 }],
          members: [
            { member_id: 11, name: '홍길동', allocation: 180000, used: 52000, remaining: 128000, ratio: 0.288 },
            { member_id: 12, name: '김철수', allocation: 180000, used: 0, remaining: 180000, ratio: 0 },
          ],
        }),
      );
    }
```

기존 catch-all(`/api/members` 응답)은 그대로 둔다. 기존 단언 4건이 전부 통과해야 한다 —
특히 `:70`의 `member_id === 12`와 `:82-88`의 이름 배열이 회귀 방지의 핵심이다.

### 4.2 신규 테스트 — `test/nl-agent-member-balance.test.js`

검증 항목:

1. `createToolkit()`의 `members[]`에 `remaining`이 병합돼 있다 (홍길동 → 128000).
2. `buildSystem(toolkit)` 출력에 팀원 이름과 그 잔액이 **같은 줄에** 등장한다.
3. `dashboard.members`가 `[]`일 때도 `buildSystem`이 예외 없이 기존 형식으로 렌더된다.
4. `members[].id`가 보존돼 이름 해석이 깨지지 않는다.

**선행 작업:** `buildSystem`이 현재 module-private다(`nl-agent.js:14`). 테스트하려면
`export function buildSystem`으로 바꿔야 한다. `budgetSummary`(`:50`)가 이미 같은 이유로
export된 선례가 있으므로 컨벤션에 어긋나지 않는다.

## 6. 범위 밖

- **teamMoneyManager 서버 변경** — 불필요(데이터는 이미 완전하다)하며 프로젝트 규칙상 금지.
- **개인 잔액 조회용 신규 LLM 도구** — 라운드 1회를 소모해 5초 예산을 위협한다.
  `list_members` 제거 전례(`tools.js:14-17`)와 같은 이유로 채택하지 않는다.
- **과거 월 개인 잔액 조회** — 서버가 과거 월에는 `members: []`를 반환한다
  (`teammoneymanager/src/server.js:1329`, 스냅샷 인원만 신뢰하는 정책). 당월 한정으로 둔다.
  요구가 생기면 서버 정책 변경이 선행돼야 하는 별도 과제다.
